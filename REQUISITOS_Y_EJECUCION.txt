================================================================================
 EXPOTÉCNICA 2026 - GUIA COMPLETA PARA QUE EL PROYECTO FUNCIONE CORRECTAMENTE
================================================================================

Sistema de gestión y calificación de proyectos (Laravel 13 + MySQL + Blade/Bootstrap).


--------------------------------------------------------------------------------
1. REQUISITOS DEL SISTEMA
--------------------------------------------------------------------------------

Software necesario:
  - PHP                >= 8.3   (con las extensiones de la seccion 2)
  - MySQL              >= 5.7   (base de datos "expo", ver seccion 4)
  - Composer           2.x
  - Node.js            >= 20    (y npm, para el frontend con Vite)
  - Git                (opcional, para clonar)

Extensiones PHP obligatorias (php.ini):
  - pdo_mysql      (conexion a MySQL)
  - mbstring       (manejo de texto/acentos)
  - openssl        (seguridad, correos, firma de enlaces)
  - fileinfo       (validacion de archivos/PDFs)
  - gd  o  imagick (generacion de PDFs con DomPDF e imagenes)
  - xml, ctype, tokenizer, json, curl, zip
  - bcmath         (recomendado)

Para verificar tu PHP:  php -v   y   php -m


--------------------------------------------------------------------------------
2. INSTALACION PASO A PASO (PRIMERA VEZ)
--------------------------------------------------------------------------------

  1) Clonar/descargar el proyecto y entrar a la carpeta.

  2) Instalar dependencias de PHP:
        composer install

  3) Crear el archivo .env a partir del ejemplo:
        copy .env.example .env        (Windows)
        cp .env.example .env          (Linux/Mac)

  4) Editar el .env con tus datos reales (ver seccion 4).

  5) Generar la llave de la aplicacion (OBLIGATORIO):
        php artisan key:generate

  6) Crear la base de datos en MySQL (si no existe):
        - Abrir MySQL (por ejemplo con phpMyAdmin o consola) y crear la BD "expo".
        - Alternativa: crear la base en el .env (DB_DATABASE) y luego:
              php artisan migrate   (crea todas las tablas)

  7) Sembrar datos iniciales (roles, rubricas, categorias y usuarios de prueba):
        php artisan db:seed

  8) Enlace del storage (para que imagenes y PDFs sean publicos):
        php artisan storage:link
        (Debe crear public\storage -> storage\app\public. Si ya existe, no pasa nada.)

  9) Instalar y compilar el frontend (Vite):
        npm install
        npm run build

  10) Ejecutar la aplicacion (ver seccion 5).


--------------------------------------------------------------------------------
3. CONFIGURACION DEL ARCHIVO .env
--------------------------------------------------------------------------------

Valores esenciales que DEBEN estar bien:

  APP_NAME=ExpoTECNICA
  APP_ENV=local                -> "production" cuando este en produccion
  APP_DEBUG=true               -> PONER EN false EN PRODUCCION (no mostrar errores)
  APP_URL=http://127.0.0.1:8000

  DB_CONNECTION=mysql
  DB_HOST=127.0.0.1
  DB_PORT=3306
  DB_DATABASE=expo             -> nombre de tu base de datos
  DB_USERNAME=root             -> usuario de MySQL
  DB_PASSWORD=                 -> contrasena de MySQL

  QUEUE_CONNECTION=database    -> LOS CORREOS VAN POR COLA (ver seccion 6)
  SESSION_DRIVER=database
  CACHE_STORE=database

  FILESYSTEM_DISK=local        -> el codigo usa el disco "public" directamente

  MAIL_MAILER=smtp
  MAIL_HOST=smtp.gmail.com
  MAIL_PORT=587
  MAIL_USERNAME=tu-correo@gmail.com
  MAIL_PASSWORD=contraseña-de-aplicacion
  MAIL_FROM_ADDRESS=tu-correo@gmail.com
  MAIL_FROM_NAME="${APP_NAME}"
  MAIL_ENCRYPTION=tls

  IMPORTANTE: Para Gmail debes usar una "contraseña de aplicacion"
  (no la contrasena normal) y activar el acceso de apps menos seguras / 2FA.


--------------------------------------------------------------------------------
4. BASE DE DATOS
--------------------------------------------------------------------------------

  - La aplicacion usa MySQL con la base "expo".
  - Tablas se crean con:            php artisan migrate
  - Si algo falla, revisar credenciales en el .env (seccion 3).
  - Datos de prueba (sembrados con php artisan db:seed):

      ADMINISTRADOR
        Correo:  admin@test.com
        Clave:   password

      JUECES (juez1@test.com, juez2@test.com, juez3@test.com)
      SUPLENTES (suplente1@test.com ... suplente4@test.com)
      ESTUDIANTES (estudiante1@test.com ... estudiante4@test.com)
      -> Todos usan la clave: password


--------------------------------------------------------------------------------
5. EJECUTAR LA APLICACION (DESARROLLO)
--------------------------------------------------------------------------------

  OPCION A - Todo en uno (servidor + cola + logs + Vite):
        composer dev

  OPCION B - Manual, en tres terminales:

    Terminal 1 - Servidor web:
        php artisan serve
        -> Abrir en el navegador: http://127.0.0.1:8000

    Terminal 2 - Worker de cola (OBLIGATORIO, ver seccion 6):
        php artisan queue:work --queue=emails

    Terminal 3 - Frontend (solo en desarrollo, con cambios en vivo):
        npm run dev


--------------------------------------------------------------------------------
6. WORKER DE COLA - CRITICO PARA EL ENVIO DE CORREOS
--------------------------------------------------------------------------------

Los correos (cuenta creada, evaluacion completada) se ENCOLAN en la tabla "jobs".
Para que se envien, DEBE haber un worker corriendo TODO EL TIEMPO:

        php artisan queue:work --queue=emails --sleep=3

  - Si el worker NO esta activo: el sistema funciona normal, pero los correos
    quedan pendientes en la tabla "jobs" y NO se envian.
  - Cuando enciendas el worker, envia los que estaban pendientes.
  - Es un proceso de fondo: se inicia una vez y queda escuchando.
    Se reinicia si la PC se apaga o el proceso se detiene.

  Produccion (Windows) - instalar como servicio con NSSM:
        nssm install ExpoQueue "C:\ruta\a\php.exe" "artisan queue:work --queue=emails --sleep=3"
        nssm set ExpoQueue AppDirectory "C:\Users\User\Desktop\Proyectos\Calificacion_Proyectos"
        nssm start ExpoQueue

  Produccion (Linux) - usar systemd o supervisor (worker permanente).

  Opcional: si quieres enviar correos INSTANTANEOS sin worker (NO recomendado
  en produccion), cambiar en .env:  QUEUE_CONNECTION=sync


--------------------------------------------------------------------------------
7. COMANDOS UTILES DE MANTENIMIENTO
--------------------------------------------------------------------------------

  Limpiar cache / config / vistas:
        php artisan optimize:clear

  Limpiar solo la cola de jobs (ojo: pierde correos pendientes):
        php artisan queue:clear

  Ver trabajos fallidos:
        php artisan queue:failed
  Reintentar trabajos fallidos:
        php artisan queue:retry all

  Compilar el frontend:
        npm run build          (produccion)
        npm run dev            (desarrollo, con recarga)

  Crear el enlace del storage (si las imagenes/PDFs no se ven):
        php artisan storage:link


--------------------------------------------------------------------------------
8. NOTAS IMPORTANTES DE PRODUCCION
--------------------------------------------------------------------------------

  - APP_DEBUG=false  (no mostrar errores ni datos sensibles)
  - APP_URL con el dominio real.
  - Correr el worker como servicio (seccion 6).
  - Correr  php artisan config:cache  y  php artisan route:cache
  - Hacer  npm run build  (no usar npm run dev).
  - La contrasena inicial de los usuarios es su cedula y debe cambiarse.


--------------------------------------------------------------------------------
9. ESTRUCTURA PRINCIPAL DEL PROYECTO
--------------------------------------------------------------------------------

  app/Http/Controllers   -> Logica de negocio
  app/Models             -> Modelos Eloquent
  app/Mail               -> Plantillas de correo (CuentaCreadaMail, EvaluacionCompletadaMail)
  app/Jobs               -> Trabajos en cola (EnviarCorreoEvaluacionJob)
  app/Http/Middleware    -> Middlewares (AdminMiddleware, rol administrador)
  resources/views        -> Vistas Blade (admin, juez, proyectos, emails, pdf)
  routes/web.php         -> Todas las rutas del sistema
  database/migrations    -> Esquema de la base de datos
  database/seeders       -> Datos iniciales de prueba
  storage/app/public     -> Archivos subidos (imagenes, PDFs de proyectos y evaluaciones)
